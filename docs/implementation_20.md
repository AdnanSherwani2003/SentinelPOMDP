# Implementation 20 — final controlled validation

I20 audits and prepares the integrated project for a local, reproducible portfolio
demonstration. It preserves the mathematical architecture and research findings.
Confirmed defects are tracked in reports/implementation20/issue_register.md.

Changes include consistent draft-only domain uploads, reviewed metadata protection,
single-process launcher/concurrency validation, correct worker health semantics,
locked development test dependencies, broader redacted release auditing, source
staging proposals, Apache-2.0 licensing, and isolated synthetic setup/validation tools.
It also closes stale-checkpoint source validation and partial required-fact
coverage defects, and rejects invalid legacy belief inputs without changing valid
mathematics.

Read architecture.md, quickstart.md, developer_guide.md, evaluation_summary.md,
security_and_trust_boundaries.md, deployment_runbook.md and the case study for the
current view. Historical implementation reports are retained as historical evidence.

Public test counts, aggregate backup/browser/research evidence and restrictions
are in [release validation](release_validation.md). Local audit inventories,
original-row operational reports and the exact Git checkpoint proposal remain
private review materials, not public setup prerequisites.
Nothing in this milestone authorizes automatic staging, committing, publishing,
paid inference, model activation on research data, or further persistent Olist import.
